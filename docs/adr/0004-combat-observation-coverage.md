# ADR 0004. Архитектура боевого наблюдения после расширения покрытия

## Критерий

Приёмка требует 90% дедуплицированных боевых решений на проверочной выборке и отдельного подтверждения на запущенной игре. Легальные действия, цели, классы, маскированные токены и логиты должны совпадать с оригинальной моделью под тем же профилем видимости. Офлайн-проверка неизвестного параметра не входит в числитель этих метрик.

**Рекомендация — NO-GO для дальнейшего расширения текущего подхода через добавление отдельных механик.** Сохранить строгий адаптер и тесты как эталон проверки. Поддержка шести реликвий и пяти частых эффектов подняла регрессию до 38,9%. Результат на новых seed — 27,1%, в актах 2 и 3 около 14%. На новой выборке набор основных блокирующих эффектов сместился к Confused, Aggression и Juggernaut. Продолжение по одному эффекту не подтверждает путь к 90% на репрезентативном наборе решений.

| Подход | Что переиспользуется | Ограничения |
| --- | --- | --- |
| Текущая реконструкция из публичного снимка | Нативные импорт, правила, encoder и forward pass | Строгая проверка обнаруживает расхождения. По мере продвижения по актам растёт число сочетаний, для которых один снимок не подтверждает все необходимые промежуточные параметры. |
| Публичное наблюдение с формальным контрактом признаков и проверяемой историей | Оригинальный encoder и нативные расчёты, для которых upstream предоставляет интерфейсы | Нужен явный перечень реально используемых признаков, включая RL2, и тесты эквивалентности. Наблюдаемая история должна иметь начало и проверяемую полноту при восстановлении соединения. Любой признак со скрытым входом требует отдельного решения upstream. |
| Точное перечисление состояний для небольших неизвестных величин | Оригинальные легальность, encoder и веса для каждого варианта | Полезно как инструмент аудита. Число вариантов растёт при нескольких неизвестных, полный вывод возможен только при доказанной конечности доменов и совпадении всех результатов. В этой итерации доступен только офлайн-PoC. |

Предпочтительный следующий эксперимент — согласовать с upstream контракт публичных признаков для одного боевого решения и проверить его на стратифицированных позициях с полным набором состояний. PoC прямых классов из ADR 0003 задаёт уже проверенную часть. Полный перенос encoder или RL2 создаст вторую реализацию боевых правил и разойдётся с исходной моделью.
