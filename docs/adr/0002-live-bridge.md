# ADR 0002. Read-only Advisor bridge

**Принято для SM-02.** Клиент подключается к TCP JSON Lines Advisor Mode закреплённого Spire Mentor 0.11.10 на `127.0.0.1`. Upstream-мод отправляет `advice_request` без ожидания вычислений в интерфейсе. Расширение SpireMind добавляет позиционные подтверждения и передачу видимой карты в боевом запросе. SpireMind использует отдельный клиент и только функции реконструкции из `sts2-advisor`. [Протокол Advisor](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/spire-mentor-mod/PROTOCOL.md) · [Реконструкция upstream](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-advisor/src)

Поддерживается одна сессия TCP за раз. Идентификаторы `a<N>` и `state_id` повторно проверяются. Единственный записываемый в сокет тип — `advice` с `hand_back`, парой идентификаторов и capability для уведомлений о действиях. Подтверждение завершает in-flight запрос мода и включает `human_action`, `combat_ended`, `game_over`. Оно не содержит `best`, `options`, route или полей исполнения. Пакет с типом Autopilot закрывает соединение без ответа. Рекомендации остаются в терминале. [Обработка ответов в моде](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/spire-mentor-mod/SimAdvisor.cs)

На входе действует allowlist протокольных полей с вложенными схемами. Seed, RNG, неизвестный порядок добора, автомат врага и закрытые данные очередей не передаются реконструктору. Стопка добора представлена отсортированным мультимножеством. Внутренний placeholder seed upstream применяется для создания объекта, затем граф карты и показанные боссы берутся из наблюдения. При наличии предупреждений реконструкции совет не выдаётся. В forward pass сохраняется маска прогноза намерений SM-01. Для стоящих на карте боссов используются видимые идентификаторы текущего акта. В бою сверяются показанные намерения, карточные индексы, наблюдаемая цена и цели. Ограниченные случаи без достаточной информации, включая часть зелий, сил и скрытых счётчиков, возвращают `blocked`.

Расширение добавляет в `combat_action` текущий актовый граф, который игрок может проверить на карте во время боя. Используется штатный `SerializeMapGraph`. Свежая карта принимается, если текущая координата совпадает с последней посещённой. При отсутствии карты допускается только карта из подтверждённого перехода в текущей сессии. Для такого перехода сверяются `advice_request_id`, `position_id` и индекс предложенного узла. `snapshot_saved` снимает действующий совет и сохраняет ожидаемую корреляцию. `snapshot_restored` и `combat_undone` очищают карту. Мод показывает начальный единственный узел `Monster (3,0)` отдельно от графа первого ряда. Этот выбор выводится как `forced` по данным экрана. Replay принимает полный санитизированный снимок с картой.

Один поток вычислений владеет однажды загруженной моделью. Reader ограничивает размер строки 256 КиБ, ждёт не более двух секунд на частично полученную строку и заменяет единственную ожидающую работу самым свежим кадром. Producer и клиент согласуют `capabilities.spiremind_lease=1`. Producer проверяет эпоху, соединение, активный экран и существенные параметры видимых вариантов. `spiremind_confirm` содержит пару идентификаторов запроса и состояния и строго возрастающий `lease_seq`. Публикация ждёт первого подтверждения. Следующие подтверждения продлевают TTL без обращения к модели. При изменении состояния producer отправляет `spiremind_withdraw`. Потеря связи или слишком длинная пауза отменяет совет. Переподключение требует нового запрошенного снимка, поэтому запоздалый кадр не возобновляет отменённую рекомендацию. `pong` игнорируется.

Одинаковые санитизированные входы, полученные соседними запросами в одной сессии, могут использовать последний рассчитанный результат. Сравнение включает порядок карты в руке и индексы целей. Вычисленный ранее `forward_ms` в таком событии отсутствует. Исторические события JSONL учитывают `stale` и `confirmed`. Адаптер не измеряет захват-до-результата, поскольку протокол не даёт метку времени захвата.

Модель и движок SM-01 остались закреплены. Для `v0.111.1` применена отдельная строгая пара, потому что исходники закреплённого upstream указывают эквивалентность конкретного стабильного коммита `cc1f9462` с исходной `v0.111.0` `41cef1ea`. Это основание для попытки реконструкции, статус реальных наблюдений публикуется отдельно. Другие hotfix и beta пары отклоняются. `sts2-advisor` подтягивает ONNX-зависимости сборки через workbench, но этот клиент не вызывает их и не загружает другие модели. На Windows требуются современные MSVC инструменты, на macOS проверяется офлайн-сборка.
