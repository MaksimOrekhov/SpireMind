# ADR 0002. Read-only Advisor bridge

**Принято для SM-02.** Клиент подключается к TCP JSON Lines Advisor Mode закреплённого Spire Mentor 0.11.10 на `127.0.0.1`. Нового мода или игрового движка не требуется. В этом режиме Mod отправляет `advice_request` без ожидания вычислений в UI. Обычный SimAdvisor также умеет предлагать игровые действия, пользоваться зеркалом RNG и переключаться на search. SpireMind использует отдельный клиент и только функции реконструкции из `sts2-advisor`. [Протокол Advisor](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/spire-mentor-mod/PROTOCOL.md) · [Реконструкция upstream](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-advisor/src)

Поддерживается одна сессия TCP за раз. Идентификаторы `a<N>` и `state_id` повторно проверяются. Единственный записываемый в сокет тип — `advice` с `hand_back`, парой идентификаторов и capability для уведомлений о действиях. Подтверждение завершает in-flight запрос мода и включает `human_action`, `combat_ended`, `game_over`. Оно не содержит `best`, `options`, route или полей исполнения. Пакет с типом Autopilot закрывает соединение без ответа. Рекомендации остаются в терминале. [Обработка ответов в моде](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/spire-mentor-mod/SimAdvisor.cs)

На входе действует allowlist протокольных полей с вложенными схемами. Seed, RNG, неизвестный порядок добора, автомат врага и закрытые данные очередей не передаются реконструктору. Стопка добора представлена отсортированным мультимножеством. Внутренний placeholder seed upstream применяется для создания объекта, затем граф карты и показанные боссы берутся из наблюдения. При наличии предупреждений реконструкции совет не выдаётся. В forward pass сохраняется маска прогноза намерений SM-01. Для стоящих на карте боссов используются видимые идентификаторы текущего акта. В бою сверяются показанные намерения, карточные индексы, наблюдаемая цена и цели. Ограниченные случаи без достаточной информации, включая часть зелий, сил и скрытых счётчиков, возвращают `blocked`.

Штатный combat-пакет не содержит карты. Клиент хранит видимую карту текущего акта и принимает переход по `human_action` только при совпадении `advice_request_id`, `position_id` и индекса предложенного узла. При потере корреляции или смене сессии он требует новое наблюдение. `snapshot_saved` снимает действующий совет и сохраняет ожидаемую корреляцию, поскольку мод отправляет его перед подтверждением перехода. `snapshot_restored` и `combat_undone` очищают карту. Мод показывает начальный единственный узел `Monster (3,0)` отдельно от графа первого ряда. Этот выбор выводится как `forced` по данным экрана. Replay принимает полный санитизированный снимок с картой.

Один поток вычислений владеет однажды загруженной моделью. Reader ограничивает размер строки 256 КиБ, ждёт не более двух секунд на частично полученную строку и заменяет единственную ожидающую работу самым свежим кадром. Перед выводом результат повторно сопоставляется с идентификатором сессии, позиции и сроком действия. Переходы, о которых producer не уведомил, ограничены TTL. Исторические события JSONL должны читаться с учётом `stale`. Адаптер не выдаёт захват-до-результата, поскольку протокол не даёт метку времени захвата. TLS и удалённые адреса не нужны для локального loopback.

Модель и движок SM-01 остались закреплены. Для `v0.111.1` применена отдельная строгая пара, потому что исходники закреплённого upstream указывают эквивалентность конкретного стабильного коммита `cc1f9462` с исходной `v0.111.0` `41cef1ea`. Это основание для попытки реконструкции, статус реальных наблюдений публикуется отдельно. Другие hotfix и beta пары отклоняются. `sts2-advisor` подтягивает ONNX-зависимости сборки через workbench, но этот клиент не вызывает их и не загружает другие модели. На Windows требуются современные MSVC инструменты, на macOS проверяется офлайн-сборка.
