## Локальная сборка мода, если Workshop недоступен

Официальная страница Workshop по ссылке upstream при проверке ответила HTTP 500. Закреплённый Spire Mentor собран с .NET SDK `9.0.321` против собственной установленной `v0.111.1`. Сборка завершилась с 18 предупреждениями исходного C# и без ошибок. BaseLib `3.4.7` скачан из официального релиза, сверена SHA‑256 архива `d28c649a3aea9ef4869050a06bfbadc4863016bcbd4c1740acc4cd07809e4bd8`. Моды установлены с согласия владельца в новые папки `mods/SpireMentor` и `mods/BaseLib`. Конфигурация мода оставляет `auto_start`, `advisor_autoplay`, `client_run_config` и `ai_partners_menu` выключенными. Версия игры и настройки Steam остались прежними. [Официальный BaseLib 3.4.7](https://github.com/Alchyr/BaseLib-StS2/releases/tag/v3.4.7)

Если установка ещё не выполнена, следующие команды готовят локальные файлы без копирования в игру. Понадобится .NET SDK 9.0 и checkout, скачанный `scripts/setup.py`.

```powershell
$game = '<каталог игры из Steam → Управление → Просмотреть локальные файлы>'
$stage = Join-Path (Get-Location) '.local/mod-stage'
$null = New-Item -ItemType Directory -Force $stage
$archive = Join-Path $stage 'BaseLib.zip'
curl.exe -fL 'https://github.com/Alchyr/BaseLib-StS2/releases/download/v3.4.7/BaseLib.3.4.7.zip' -o $archive
if ($LASTEXITCODE -ne 0 -or (Get-FileHash -LiteralPath $archive).Hash -ne 'd28c649a3aea9ef4869050a06bfbadc4863016bcbd4c1740acc4cd07809e4bd8') { throw 'BaseLib download or SHA-256 failed' }
Expand-Archive -LiteralPath $archive -DestinationPath (Join-Path $stage 'BaseLibRelease')
$base = (Get-ChildItem -LiteralPath $stage -Filter BaseLib.dll -Recurse | Select-Object -First 1).DirectoryName
$mentor = Join-Path $stage 'SpireMentor'
dotnet build .local/upstream/spire-mentor-mod/SpireMentor.csproj -c Release -o $mentor "-p:STS2_GAME_DIR=$game" "-p:BaseLibDir=$base" -p:SpireMentorSkipDeploy=true -p:SpireMentorSkipAdvisorSync=true
if ($LASTEXITCODE -ne 0) { throw 'Spire Mentor build failed' }
Copy-Item -LiteralPath '.local/upstream/spire-mentor-mod/SpireMentor.json','.local/upstream/spire-mentor-mod/SpireMentor.conf.template' -Destination $mentor
```

При закрытой игре скопируйте только `BaseLib.dll`, `BaseLib.pck`, `BaseLib.json` из `$base` в `mods/BaseLib` и `SpireMentor.dll`, `SpireMentor.json`, `SpireMentor.conf.template` из `$mentor` в `mods/SpireMentor`. Избегайте двух копий одной модификации одновременно. В меню мода выключите автозапуск advisor backend и автобой. Workshop-подписка для этой установки не нужна.

## Ручное воспроизведение

1. Запустите модифицированную игру и убедитесь, что Spire Mentor в Coach или Hints, а автоматическое управление отключено.
2. Запустите `live --release-info $release --json --capture-dir .local/live-captures` до выбора первого узла. Подключение должно отобразить `Connected. Waiting for Advisor observations.`.
3. Начните одиночный стандартный забег Ironclad A0 или A10. Сравните карту с несколькими ветками, бой с несколькими целями и дубликатами карт, карточную награду со Skip. Сделайте выбор вручную. Проверьте смену `state_id` и инвалидацию старого совета после действия. Повторите для нескольких состояний каждого типа.
4. Остановите CLI, передайте санитизированные JSON-файлы в `replay` и сравните ранжирование и `action_id` на тех же снимках. Отделите p50/p95 `receive_to_result_ms` в live-потоке от `forward_ms` и от `replay_to_result_ms`. Подсчитывайте только `status=ok` для задержки модели и отдельно сообщайте о `forced`, `blocked`, `stale`.

Никакие игровые файлы или сырые снимки не входят в Git. Параметр `--capture-dir` сохраняет только разобранное наблюдение после allowlist. Служебная функция Copy state в самом моде может оставить сырой файл вне репозитория. Для обычной проверки используйте TCP capture.

## Результат live-проверки

**PARTIAL.** Оригинальная Instinct рассчитала рекомендации на всех трёх типах реальных игровых наблюдений Windows `v0.111.1`, Ironclad A0. Ручной сценарий покрыл одну развилку и бой с одной живой целью. Для полного критерия Issue #3 остаются несколько разных развилок, реальный бой с несколькими целями и расширенная выборка задержек.

| Контекст | Начальная позиция и наблюдение | Проверенный результат |
| --- | --- | --- |
| Combat | `571`, `572`. В первой руке два обычных Strike по разным индексам, Setup Strike, Inflame и Defend. Один противник Shrinker Beetle. | Совпали шесть, затем пять действий с учётом `end_turn`. Первый совет — Inflame из слота 2. После ручного розыгрыша `571` погашен событием `player_action`, новая рекомендация — Setup Strike из слота 1 по врагу 0 (`combat_id=1`). |
| Card reward | `458`, `460`, `462`. Три предлагаемые карты и Skip. Два порядка отображения одних карт. В первом проходе отдельно наблюдалась другая тройка карт. | Модель сохранила Anger первым после изменения порядка, а её индекс предложения поменялся с 2 на 1. Ручной выбор Inflame сохранился в журнале мода. В первом проходе модель предложила Setup Strike. |
| Map | `463`, `465`. Два узла на следующем ряду. Отдельно наблюдалась карта с единственным узлом после первого боя. | Модель поставила `Unknown` (ряд 2, колонка 1) выше `Monster` (ряд 2, колонка 3). Журнал мода подтвердил, что игрок вручную выбрал `Monster`. Для карты с одним выходом получен `forced` без forward и вероятностей. |

На семи снимках из финального сеанса `replay` воспроизвёл все списки действий, идентификаторы и полное ранжирование, включая логиты и вероятности. p50/p95 replay составили 10,30/12,55 мс. Во время первоначального переподключения текущий бой без подтверждённой карты давал `missing_visible_map`. После наблюдаемого перехода мост восстановил позицию. Уведомление `snapshot_saved` при штатном переходе теперь очищает действующий совет и сохраняет только ожидаемую корреляцию выбора узла. Команды игры не отправлялись. Игровые выборы делал игрок.

## Задержка

Windows x64, AMD Ryzen 5 7600X, release-сборка, CPU. В таблице финальный живой TCP-сеанс, только `status=ok`. p50 и p95 рассчитаны методом ближайшего ранга. Две строки карты описывают одну развилку, три строки награды описывают один набор предложений. Такой объём позволяет проверить выполнение порога на наблюдавшихся кадрах. Для оценки устойчивой задержки нужна более длинная серия разных позиций. При измерении на ПК также выполнялись сборка и часть офлайн-бенчмарка. Влияние нагрузки на плавность игры отдельно не измерялось.

| Контекст | Кадры | Receive → result p50 / p95, мс | Forward p50 / p95, мс |
| --- | ---: | ---: | ---: |
| Combat | 2 | 13,79 / 16,18 | 4,73 / 5,46 |
| Card reward | 3 | 14,54 / 25,56 | 3,25 / 8,14 |
| Map | 2 | 22,20 / 30,45 | 12,96 / 18,50 |
| Все | 7 | 16,18 / 30,45 | 5,46 / 18,50 |

Receive → result начинается после приёма полной строки Advisor и включает проверку, реконструкцию, токенизацию и inference до вывода события. Время от изменения игрового экрана и отрисовка терминала здесь отсутствуют. Отдельный результат `forced` для узла карты занял 5,33–6,76 мс в первом сеансе и исключён из таблицы. Просроченные, неподдерживаемые и заблокированные позиции также исключены.

## Регрессии и оставшиеся проверки

- Windows локально: проверка чистоты закреплённых исходников, `cargo fmt --check`, Clippy с `-D warnings`, release-сборка и 12 тестов прошли. Дополнительно два smoke с настоящими весами прошли отдельно. Один запускает оригинальные регрессии SM-01, второй покрывает все три синтетических Advisor-контекста на A0 и A10. Синтетический forward занял 2,11–3,45 мс.
- Повтор исходного офлайн-бенчмарка SM-01 после выхода из игры: 10 из 10 забегов завершены, 9 побед, 7 775 решений, без ошибок, caps и тайм-аутов. Время панели 60,98 с. Forward p50/p95 составили 7,54/11,32 мс, максимум 82,93 мс. Эта серия проверяет регрессии симулятора и сохраняет исходный набор seed. [Бенчмарк SM-01 и команда](poc-results.md#бенчмарк)
- Windows и macOS CI получают закреплённые зависимости до фазы офлайн-сборки. Отдельный Windows job скачивает проверенный чекпойнт и запускает оба smoke. Игра и Steam в CI не используются.
- Live-подтверждение относится к Windows `v0.111.1` и A0. Для `v0.111.0`, A10, macOS и всех прочих сочетаний живых подтверждений в этой сессии нет. Сопоставление нескольких боевых целей и исключение мёртвых врагов проверены синтетически.
- Пока доступны состояния с доказуемыми действиями и видимыми данными. Часть таргетируемых зелий, механик питомцев и неизвестных эффектов даёт `blocked`. При открытии overlay или уходе с экрана, о котором мод не сообщил, верхняя граница видимости прошлого совета задаётся TTL. После отключения клиент ждёт новый снимок карты для боевых рекомендаций, так как мод не включает её в combat payload.
- Для завершения ручного покрытия продолжите Ironclad A0 на Windows по процедуре выше. Захватите как минимум второй иной набор доступных веток и бой с двумя или более активными целями. Сравните индексы с экраном, сыграйте одну карту вручную и прогоните эти же снимки через `replay`. Запишите больше разных позиций для оценки p95. [Требования Issue #3](https://github.com/MaksimOrekhov/SpireMind/issues/3)
