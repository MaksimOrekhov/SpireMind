## Движок, CLI и обучение

- `sts2-core` и `sts2-content` задают правила боя и забега. `sts2-wire` задаёт структуры легальных действий и снимков. `sts2-e2e` предоставляет `env`, `snapshot`, `tokens` и `net`. Модель оценивает объединённые классы, а `Decision.actions` и `Decision.members` сохраняют конкретные экземпляры и цели. PoC использует этот API напрямую. [Архитектура upstream](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/ARCHITECTURE.md) · [Rust inference](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-e2e/src)
- Штатный `sts2-cli` обслуживает симуляцию и анализ. `sts2-e2e/examples/play.rs` ведёт забег через `E2eEnv → encode_for → E2eNet::act_greedy` и выводит статистику по seed. Этот путь подтверждает способ подключения и даёт независимую точку сравнения выбора на той же позиции. [Штатный Rust CLI](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-cli) · [Пример play](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-e2e/examples/play.rs)
- `sts2-py` предоставляет Rust API через PyO3. `sts2-pycli` декларирует Python ≥3.13, `uv` и PyTorch для собственного стека. `ppo/e2e/learner.py` ведёт PPO, optimizer, EMA и stamps. `export_wb` создаёт `.e2ew` из `.pt`. Релизный `.pt` содержит policy и value head, исходный optimizer в релизе отсутствует. Для будущего warm-start надо закрепить тренер, входную схему, словарь, версию игры и отдельную панель оценки. [PyO3 bindings](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-py) · [PPO и экспорт](https://github.com/tfriedel/spire-mentor/tree/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-pycli/python/ppo/e2e) · [Документация обучения](https://tfriedel.github.io/spire-mentor/training.html)
- На Windows x64 нативный путь проверен с Rust `1.99.1`, MSVC и Windows SDK. На macOS нативный путь требует Rust и Xcode Command Line Tools. Дополнительный CI runner проверяет сборку и контракты на arm64. Сборка C#-мода — отдельный Windows workflow с .NET 9, BaseLib и собственной Steam-установкой. Режимы мода заявлены для `v0.111.1` и `v0.113.0`. Этот диапазон не расширяет pin SM-01 `v0.111.0`. [Windows build](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/BUILDING-WINDOWS.md) · [Требования мода](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/spire-mentor-mod/README.md)

## Входные данные policy

`E2eEnv` использует seed для воспроизводимой симуляции. `tokens::encode` вызывает `encode_with` с выключенным `priv_`. Поле `seed` из `run_obs` отсутствует в `PolicyRow`. `snapshot::belief_view` представляет неизвестный участок стопки добора каноническим мультимножеством и заменяет реальные RNG-курсоры своими. Зафиксированные игроком позиции карт сохраняются. История намерений строится из уже показанных намерений, карта содержит видимую топологию и боссов текущего акта, предложения наград берутся с открытого экрана. Очереди будущих рядовых боёв, элит и событий не передаются модели. [Encoder](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-e2e/src/tokens.rs) · [Combat snapshot](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-e2e/src/snapshot.rs)

Даже в policy режиме upstream кодирует три прогнозируемых хода из внутреннего автомата врага, включая запланированное состояние после оглушения. Перед `try_logits` SpireMind ставит нули в `X_FC1..X_FC3` и связанных `E_F1_*..E_F3_*`, сохраняя текущий телеграф и известную историю. Эта маска меняет входные признаки боя и способна изменить логиты и выбор в других позициях. Тест на одинаковом боевом состоянии меняет скрытый порядок добора и RNG, затем сравнивает полную строку policy. Тесты карты и награды подменяют seed наблюдения и убирают закрытые очереди будущих комнат. Они служат регрессионной проверкой выбранных поверхностей. Полный аудит всех механик и полей live-снимков ещё предстоит.
