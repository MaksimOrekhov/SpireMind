# SM-02. Нативный боевой прототип C

**PARTIAL.** Сборка проверена против установленных сборок Slay the Spire 2 `v0.111.1` / `cc1f9462`. Для этой DLL требуется отдельное согласование установки и проверка в игре. Профиль рассчитан на стандартного одиночного Ironclad A0 и A10. Запуск требует точной пары версии и коммита из `release_info.json`.

## Боевой кадр и время жизни

Версия 1 контракта состоит из `native_current=1`, capability `spiremind_native_current=1` и общей структурной схемы. Power- и relic-счётчики, параметры экземпляров карт, текущие телеграфы и завершённые события поступают через существующий `SimStateExtractor`. Историю текущего боя представляют уже экспортируемые агрегаты, последние завершённые ходы противника и флаги выполнения. Полный журнал машины состояний и отложенный ход исключены. Для карт в руке producer выдаёт отдельный идентификатор экземпляра. Идентификатор живёт в пределах экземпляра в текущем процессе и назначается при первом появлении в руке. Индексы руки и целей действуют только для соответствующей позиции. Сопоставление целей использует upstream `BoardTargets` и `combat_id` из игры. [Схема контракта](../../patches/native-current-v1.json)

Обе стороны рекурсивно пропускают только объявленные поля и канонизируют неизвестную стопку добора как мультимножество. Состав стопки сохраняется. Позиции, UID и привязки к верхним или нижним картам исключены. Producer не читает RNG для этого боевого кадра. Rust создаёт новый seedless-контекст из видимой карты, применяет `Board` → native wire → `CombatMirror::build_state` и устанавливает бой через `Graft`. Перед encoder очищаются draw pins и сохранённые снимки хода противника, применяется `belief_root` и используется локальный детерминированный RNG. Маска входа v2 убирает прогнозы будущих ходов перед forward. Архивный C-кадр проходит ту же фильтрацию при `replay`.

Модель загружается один раз, вход соответствует стабильной фазе игры. Один вызов исходного encoder и forward выполняется после полного сравнения легальных карт, целей, использования зелий и завершения хода. `forced` означает единственное легальное действие. Несовместимость схемы, разница в действиях, предупреждение импортера либо неполный телеграф блокируют рекомендацию. Прототип не вызывает upstream `serve`, пошаговый greedy-план и search. Карточная награда и карта продолжают работать через прежние пути Instinct.

Клиент отдаёт только подтверждение Advisor с `hand_back`. Результат публикуется после позиционного подтверждения. Producer сверяет содержимое кадра при подтверждении, сохраняя TTL 1500 мс. Ручное действие, закрытие экрана и изменение кадра отзывают старую позицию. Клиент отбрасывает завершившийся поздно forward. Переподключение требует свежего подтверждённого кадра, включая текущий узел и посещённый путь для боя. Боевой объект прошлого соединения не переносится. При неизменном кадре повторный forward не нужен. Реальную стоимость сериализации при проверке примерно дважды в секунду предстоит измерить в игре.

## Сборка без установки

В PowerShell из корня репозитория с .NET SDK 9.0 и закреплёнными исходниками `scripts/setup.py` выполните следующие команды. Путь к игре можно получить из Steam через **Управление → Просмотреть локальные файлы**.

```powershell
$game = (Resolve-Path (Read-Host 'Каталог Slay the Spire 2')).Path
python scripts/prepare_observer.py --native-current --output .local/native-current-source
dotnet build .local/native-current-source/spire-mentor-mod/SpireMentor.csproj -c Release -o .local/native-current-mod "-p:STS2_GAME_DIR=$game" "-p:BaseLibDir=$game\mods\BaseLib" -p:SpireMentorSkipDeploy=true -p:SpireMentorSkipAdvisorSync=true
cargo build --release --locked
Get-FileHash -Algorithm SHA256 -LiteralPath .local/native-current-mod/SpireMentor.dll,target/release/spiremind.exe
```

После согласования и при закрытой игре сохраните установленную DLL вне каталога игры. Сверьте контрольную сумму подготовленной DLL, замените единственный файл `mods/SpireMentor/SpireMentor.dll` и повторите сверку. Для отката закройте игру и верните этот файл из резерва. Профиль и конфигурация мода используют те же файлы.

Запустите игру с модами. В Spire Mentor выберите **Coach** или **Hints**. **Auto-launch Python advisor**, **Auto Play** и **Auto Battle** должны быть выключены. Подключите советник до первого боя.

```powershell
$capture = '.local/native-current-live'
New-Item -ItemType Directory -Force $capture | Out-Null
.\target\release\spiremind.exe live --native-current --release-info "$game\release_info.json" --json --capture-dir $capture |
    Tee-Object -FilePath "$capture/events.jsonl"
python scripts/live_metrics.py "$capture/events.jsonl" --captures $capture
```

1. В первом бою оставьте руку и экран неизменными минимум 12 секунд. Ищите одно событие `ok` с `forward_ms` и последовательность `confirmed` для того же `state_id`.
2. Сыграйте первую карту вручную. Ищите `stale` для старой позиции и затем новый результат. Повторите в бою с двумя целями, проверьте соответствие имён и индексов и исключение убитого противника.
3. В стабильном бою остановите клиент через **Ctrl+C** и снова запустите его с новым файлом событий. Проверьте свежую позицию в новой сессии. Откройте следующую карточную награду и развилку карты после боя. Выберите их вручную.
4. При доступности сложной реликвии или эффекта сохраните один кадр до и после срабатывания. Этого сценария достаточно до начала полного приёмочного забега.

## Проверка предыдущих расхождений

Команда `spiremind architecture wire-diagnostic` повторяет один seed `754255493` из прежней панели. На десяти кадрах `THIEVING_HOPPER_WEAK` штатный native wire сохраняет идентификатор украденной карты и улучшение, а импорт восстанавливает запись без ссылки на экземпляр мастер-колоды. Это существенно, когда карту могли изменить в бою или в колоде есть несколько похожих экземпляров. Повторное кодирование выявило расхождение эффективной мастер-колоды, pooled tokens и логитов при совпадающих действиях, целях и классах. Профиль C блокирует бой с этим противником до получения достаточной информации об экземпляре. В игре эти расхождения пока не проверялись. [Штатное восстановление списка украденных карт](https://github.com/tfriedel/spire-mentor/blob/a7d5f4d2507afbc5db9a13879c9da77faff4a7e7/sts2-rs/crates/sts2-wire/src/state_dict.rs)

Отдельный диагностический прогон использует DTO, спроецированные из того же симуляторного забега, и запускает настоящий Rust-путь C с оригинальными весами. Он не проверяет фактические C# get-теры или сетевую задержку игры. Старые панели и тесты A, B и C сохраняются.

| Диагностический путь | Instinct | Forced | Blocked | Покрытие |
| --- | ---: | ---: | ---: | ---: |
| Исходный C с текущим объектом боя | 605 | 5 | 0 | 610/610 |
| C после исходного Rust wire roundtrip | 595 | 5 | 10 | 600/610 |
| Новый Rust-клиент C на симуляторных DTO | 591 | 5 | 14 | 596/610 (97,7%) |

Все 14 отказов нового клиента относятся к Thieving Hopper. Его диагностический путь занял 23,92 / 42,72 / 94,60 мс (p50 / p95 / max, 596 успешных позиций с учётом forced). Замер включает фильтрацию и реконструкцию. Для критерия 250 мс нужен отдельный замер от получения кадра до публикации в игре.
